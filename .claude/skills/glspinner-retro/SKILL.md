# glspinner-retro

## このスキルの立ち位置

glspinnerでの作業には、実装や規約整理のような「手を動かして何かを変える」タスクだけでなく、「ある技術トピックについて掘り下げて考え、理解を整理する」タスクも生まれる（例: 音シェーダーがなぜ単調・耳が痛いかの原因分析と学習方針の相談）。この種の議論は結論だけでなく検討過程そのものに価値があるため、`glspinner-notion-tasks`が対象とする「実行可能なタスク」とは性質が異なり、別データベースに記録する。

このスキルは「振り返りの議論を行う（必要なら）→ 内容を整理する → Notionへ記録する」という一連の流れを担当する。振り返りの議論自体に固定の型は無く、トピックに応じて臨機応変に進めてよい（`glspinner-reading`のようなコード解説プロセスを持つわけではない）。

## 前提: 対象Notion DB

登録先DBの情報（data source ID）は、SKILL.md本体にはベタ書きせず`~/.claude/notion-databases.json`（**リポジトリの外**、ユーザーのホーム配下）の`tech_retro`エントリを一次情報源として参照する。このファイルはglspinner専用ではなく、他プロジェクト（`tech-issue`/`tech-retro`/`notion-task-sync`等）とも共有するマシン単位の設定ファイルで、`{ "<key>": { "display_name": ..., "data_source_id": "collection://...", "url"?: ..., "used_by": [...] } }`というフラットな構造を持つ。「📝 振り返り」DBは`tech-retro`スキルと共有しているため、キー名も`glspinner-retro`ではなく`tech_retro`のまま（`used_by`に`"glspinner-retro"`が追加されている）。プロパティは`Name`（タイトル）・`プロジェクト`（select、他プロジェクトの振り返りとも共有する汎用DBとして設計されている）で、glspinnerからの登録では`プロジェクト`に常に`"glspinner"`を使う。このリポジトリはpublicのため、data source IDやページURLをコミットしたくないという理由でリポジトリ外に置いている。DBの切り替えが発生した場合はこの外部JSONファイルだけを更新すればよい。

`~/.claude/notion-databases.json`自体が存在しない、または`tech_retro`エントリが無い場合（新しい環境で初めて実行する場合など）は、ユーザーに実際のdata source ID等を確認して該当エントリを追記するよう促す（他プロジェクトのエントリは削除・上書きしないこと——共有ファイルのため）。

このJSONに記載のDBが見つからない・IDが変わっている等でアクセスできない場合は、決め打ちで別のDBに登録せず、`mcp__claude_ai_Notion__notion-search`で`display_name`を検索し直し、候補をユーザーに確認してから進める。確認が取れたら`~/.claude/notion-databases.json`の該当エントリも更新しておく。

## 実行手順

### 1. 振り返り対象の確認

直前の会話ですでにまとまった議論（技術的な深掘り、設計比較、実装の読み解き、学習相談など）が行われていればそれを対象とする。まだ行われていない場合は、何について振り返りたいかをユーザーに確認してから、対象トピックを掘り下げる会話を行う。観点（良かった点/問題点とその原因/今後の方向性、比較検討、等）はトピックに応じて選び、固定テンプレートを機械的に当てはめない。

### 2. 内容の整理

会話の流れをそのまま転記せず、見出し（`##`）+箇条書きで要点を整理し直す。見出しの切り方はトピックに応じて決める（固定の型は無い。例: 音シェーダーの振り返りでは「既存実装の良い点」「耳が痛い主因」「単調の主因」「伸ばし方の方向性」「実装の読み解き」「他方式との比較」という構成にした）。会話中に出てきた具体的なファイル名・行番号・コード引用は保持し、後から読み返しても意味が通る記録にする。

### 3. タイトルの決定

ユーザーがタイトルを指定していればそれをそのまま使う。指定が無ければ内容から適切な案を1つ提示し、確認を取ってから次に進む。

### 4. Notionページの作成

`mcp__claude_ai_Notion__notion-create-pages`で以下の内容のページを作成する:

- **parent**: `{"type": "data_source_id", "data_source_id": "<~/.claude/notion-databases.jsonのtech_retro.data_source_idから\"collection://\"接頭辞を除いたUUID>"}`
- **properties**:
  - `Name`: 手順3で決めたタイトル
  - `プロジェクト`: `"glspinner"`（JSON側`properties.プロジェクト.defaultOnCreate`）
- **content**（Notion Markdown本文）: 手順2で整理した見出し+箇条書き

`notion-create-pages`を呼ぶ前に、Notion Markdownの仕様（`notion://docs/enhanced-markdown-spec`）をまだ読んでいなければ一度確認しておくと安全（記法を推測で書かない）。

### 5. 結果の報告

作成したページのタイトルとURLをユーザーに報告する。

## 完了後

振り返りの中で「これは実際にやりたい」という具体的な改善アクションが見えていれば、`glspinner-notion-tasks`でタスク化するか、その場で`glspinner-design`（設計を詰める）や`glspinner-implement`（すぐ実装する）に進めるかを案内する。

## 他SKILLとの関係

- `glspinner-notion-tasks`: 実行可能なタスクをNotionの「glspinner改良タスク」DBへ登録する担当。対象DB・登録内容の性質（結論としてのタスク vs 検討過程そのもの）が異なるので混同しない。
- `glspinner-task-discovery`: コード上に残る既知ギャップの棚卸しが情報源。会話ベースの振り返りとは出発点が異なる。
- `glspinner-ideation`: ゼロからの新機能アイディア発想。振り返りの結果として新しいアイディアが浮かんだ場合はそちらへ引き継いでよい。
- `glspinner-reading`: コードの解説そのものが目的の場合はそちら。このSKILLは解説ではなく「議論した内容を記録として残す」ことが目的。
